========================================
ANALYSIS
========================================

Command ID 269 (sent at 10:21:02) should have status "superseded"
because Command ID 302 (sent at 10:45:48) is a newer command of the same type.

BUT BOTH SHOW STATUS "sent"!

This is a VoltCred backend bug - they are not updating old command status
when a new command is sent.

========================================
BUSINESS IMPACT
========================================

1. Dashboard shows TWO pending lock commands (confusing to users)
2. Cannot determine which command is actually active
3. Lock state is ambiguous (is vehicle locked or not?)
4. Customers lose trust when they see old commands still "pending"

========================================
REQUEST TO VOLTCRED
========================================

Please fix the status update logic:
- When a new command of the same type is sent
- Mark all previous commands of that type as "superseded"
- Only the NEWEST command should have status "sent"/"delivered"/"completed"
